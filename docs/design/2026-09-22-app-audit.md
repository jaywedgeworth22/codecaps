# CodeCaps App-Wide Design Audit — 2026-09-22

A top-to-bottom UI review of every owner-facing surface on both Mac
(`Sources/CodeCaps/`) and iOS (`ios/CodeCapsCompanion/`), after the recent
Glance popover polish (PRs #38, #39).  The brief: make sure the app is as
aesthetically pleasing and intuitive as the reference design language, and
group the findings into shippable batches.

## Reference design language

The yardstick every finding is measured against.  Defined here once so a
"design is wrong" claim can be defended against a single rubric.

- **Restraint over delight.**  A status-item surface is not a store shelf.
  Every pixel earns its place by communicating quota state, not by
  demonstrating technique.  Apple HIG calls this "self-evident UI"; the
  reference surfaces in this rubric read as "made by no one", which is what
  "just works" feels like from the user's seat.
- **System theme by default.**  Reversed from "light" in 2026-09-19
  (`/Users/jay/apps/FLEET-UI-COPY.md`); captured in fleet memory.
- **Two literal spaces between sentences** in every owner-visible string
  (file convention; chat mirrors it).  Consistent across the brand.
- **Title Case for buttons, headings, titles.**  Sentence case for values
  and status text.
- **Custom Theme palette, not the system blue.**  #087370 is the CodeCaps
  accent; the menu bar, sidebar selection, and reset-alarm affordances
  should all pull from `Theme.accent`.  Any system blue that appears is a
  bug.
- **One number per row.**  A row's primary signal is the percent remaining;
  everything else (title, subtitle, countdown) is supporting prose.  A row
  that fights for attention across more than one band is competing with
  itself.
- **Respect the user's fatigue.**  The popover is opened dozens of times a
  day.  Its chrome must not draw the eye; if you have to look at it to read
  it, you will stop opening it.

The Vercel-canonical landing page (`/`) and the CodeCaps landing surface
(`https://codecaps.simplewithus.com/`) are useful references for *what
"clean data display"* looks like: a single typeface pair, a single accent,
clear typographic hierarchy, generous whitespace.  See § Open Questions for
the `home.jays.services` thread.

## Findings

Severity legend: **P0** = ship-blocker; **P1** = polish clear smell; **P2** =
audit-grade refinement; **P3** = nice-to-have.  File references are
`path:line`.

### F-01 Console sidebar is too narrow and not adjustable  **P0**

- **Where**: `ConsoleViews.swift:131` (`Metrics.sidebarWidth: CGFloat =
  200` at `QuotaComponents.swift:63`); comment at `ConsoleViews.swift:121`
  defends the flat `HStack` choice.
- **Symptom**: When a pool name is shown under "Antigravity", the row is
  the narrowest thing on the screen.  Long platform titles tail-truncate
  in the middle; the percent trailing column has no breathing room.
- **Cause**: A fixed 200pt column with no resize affordance.  The
  comment asserts this is the design intent, but the design isn't
  load-bearing — the user wants to widen or narrow the column.
- **Fix**: Move from `HStack + List(.sidebar)` to `NavigationSplitView`
  with a `navigationSplitViewStyle(.balanced)`, which gives the native
  drag-handle between sidebar and detail and re-uses the rest of the
  sidebar view.  Default sidebar width 240pt, min 200pt, max 400pt; the
  user's choice persists in `defaults` (`consoleSidebarWidth` key).
- **Why P0**: This was literally the user's opening line in the audit
  request — "the sidebar is too narrow and not adjustable."

### F-02 iOS app hardcodes red / orange / green, bypassing Theme  **P2**

- **Where**: `CompanionQuotaModel.swift:21-26`
  (`statusColor`).
- **Symptom**: An iOS user sees `Color(red: 0.90, green: 0.25, blue:
  0.25)` regardless of theme.  The macOS app uses `Theme.accent` for
  available, `Theme.warning` for near-cap, `Theme.danger` for exhausted.
- **Cause**: The iOS app imported `SwiftUI` but never imported the
  `Theme` enum (which lives in the macOS target, not the iOS app target).
  The author reached for hand-picked hues.
- **Fix**: Move the three tokens to `ios/CodeCapsCompanion/App/Models/CompanionTheme.swift`
  matching the macOS values: `accent = 0x087370`, `warning = 0xA85C05`,
  `danger = 0xBF3339`.  Reuse the same hex convention as `QuotaComponents.swift`.
- **Why P2**: Visible inconsistency between platforms; user explicitly
  asked for "as aesthetically pleasing … on both Mac and iOS".

### F-03 iOS app does not expand rows; user has to enter detail  **P2**

- **Where**: `CompanionContentView.swift:98` (`quotaCard`).
- **Symptom**: macOS Glance popover *just gained* click-to-expand rows
  (`GlanceViews.swift:206`, PR #38).  iOS still requires a tap that
  doesn't exist — every quota gets a full card and the user must leave
  the list to compare windows inside one platform.
- **Cause**: The iOS app was designed before the macOS polish; it has no
  notion of "expanded".
- **Fix**: Mirror the macOS pattern: tap a card to show a child list of
  windows (label · % remaining · reset countdown).  A chevron in the
  card, `.animation(...)`, same restraint.
- **Why P2**: Mirrors a feature the user just shipped.

### F-04 iOS refresh alert uses `UNUserNotificationCenter` even when in-foreground  **P2**

- **Where**: `CompanionQuotaModel.swift:181` (`sendResetAlert`).
- **Symptom**: A reset that fires while the user is on the iOS app's
  main screen produces a system banner that interrupts whatever they
  were looking at, instead of updating the row in place.
- **Cause**: Local notifications without `UNUserNotificationCenterDelegate.willPresent`.
- **Fix**: Set a delegate at app launch that returns
  `[.banner, .sound]` for in-foreground delivery, and re-emit a local
  banner only when the app is backgrounded.  Pair with an in-list
  "Reset" pulse animation so the change is visible wherever the user
  happens to be.
- **Why P2**: Polished alert behaviour is part of "intuitive".

### F-05 iOS settings sheet covers the entire screen  **P2**

- **Where**: `CompanionContentView.swift:50` (`.sheet(isPresented:)`),
  Defaults to full-screen on compact widths.
- **Symptom**: On iPhone, opening Settings hides the quota list, so a
  user who toggles "Notify on Quota Reset" can't see the row they
  intended to monitor.
- **Cause**: Default `.sheet` presentation.
- **Fix**: Present as `.sheet` with `.presentationDetents([.medium,
  .large])` so the list stays visible underneath.  Add a "Done" button
  that mirrors the existing `confirmationAction` toolbar.
- **Why P2**: One-line fix; high perceived-quality uplift.

### F-06 Console toolbar packs five controls into a 960pt title row  **P1**

- **Where**: `ConsoleViews.swift:200` (`toolbar`).
- **Symptom**: The All Platforms toolbar carries page title (20pt
  rounded), `Compact / Detailed` segmented control (168pt), `Find a
  Platform` search field (180pt), Refresh button, Keep-In-Front pin.
  When the window is at the 820pt minimum, the page title truncates
  with `…` between words.  Settings pages hide the picker and the
  search field but still carry Refresh + Pin + page title in 820pt,
  which is fine, so the All Platforms toolbar is the only victim.
- **Cause**: Toolbar width wasn't looked at across the title row's
  varying content widths.
- **Fix**: Drop the segmented `Compact / Detailed` control to a
  separate "View Options" menu (gear icon next to Refresh), and bring
  the `Find a Platform` field closer to the title (after the page
  title, before the trailing icons).  Give page title `minWidth: 200`
  + `layoutPriority(1)`.
- **Why P1**: Tiny fix; visible at every Console open on a 13" screen.

### F-07 Console window minimum size 820×560 is below the 200pt sidebar + 12pt divider + a useful detail pane  **P2**

- **Where**: `QuotaComponents.swift:62` (`consoleMin`).
- **Symptom**: At 820×560 the detail pane gets ~580pt wide; that is
  fine for a 240pt card grid, but the All Platforms summary tiles
  refuse to lay out cleanly because the adaptive `LazyVGrid` looks for
  `minimum: 150` and ends up at 4 tiles per row, then the search field
  loses its room.
- **Cause**: Console was sized for the smaller aggregate (sidebar +
  single column) before the summary tile row + the toolbar fixes were
  layered on.
- **Fix**: Bump `consoleMin` to 880 × 600.  Refresh autosave state of
  the window if it was previously saved at the smaller size — `setFrameUsingName`
  will move the window up.
- **Why P2**: Ensures the polish the user just saw fits at all common
  window sizes.

### F-08 Theme.dark is hardcoded to `#1C1E20`; no warm dark variant  **P3**

- **Where**: `QuotaComponents.swift:13`.
- **Symptom**: Pure neutral dark.  Some users prefer a warmer palette
  on dark themes; the current palette is correct, just monochrome.
- **Cause**: Intentional restraint.
- **Fix**: Keep as-is unless the user asks.
- **Why P3**: Note only; ship nothing.

### F-09 "Keep In Front" pin shows on every Console page, including settings  **P3**

- **Where**: `ConsoleViews.swift:255`.
- **Symptom**: A user who only opens Settings doesn't need a `pin`
  toggle in their toolbar.
- **Cause**: History.
- **Fix**: Move `Keep In Front` to `Settings → Appearance`; leave it as
  a status item command in the right-click menu (`viewKeepInFront`).
- **Why P3**: Toolbar density reduction, not a defect.

### F-10 iOS app does not deduplicate by provider in fleet pulls  **P2**

- **Where**: `CompanionQuotaModel.swift:138` (`parseSnapshot`).
- **Symptom**: Two machines' Antigravity readings show up as six cards
  on iOS instead of two.  macOS handles this via
  `AntigravityQuotaGroups` and the pool split, but the iOS parser is
  raw.
- **Cause**: The iOS app folds every window directly into a
  `CompanionQuotaItem` and never groups.
- **Fix**: Group by `providerKey` and pick the lowest remaining %
  `displayPercent` for the headline; offer a "Show all windows" toggle
  in the card's expanded view.
- **Why P2**: Same UX problem the Glance expansion addresses.

## Open questions

1. **The user reference**.  The brief mentioned "I like how on
   home.jays.services I think we are displaying the data too, right?".
   Fetching `https://home.jays.services/` today returns the **Vercel
   sign-in page**, not an owner-built surface.  Either the user is
   remembering a site they planned to deploy there, or they're
   thinking of `https://codecaps.simplewithus.com/` (the CodeCaps
   landing) or `https://jays.services/` (the Personal-Site).  Worth
   confirming before refining the visual language further.
2. **Sidebar width ceiling**.  F-01 lands 240 default + 200–400 range.
   If there's an existing preference (e.g., owners who set 200 because
   of vertical-density preferences on 13" screens), we'd want to
   preserve their stored value rather than reset to 240.
3. **Mac iconography parity on iOS**.  `Sources/CodeCaps/Resources/ProviderMarks/`
   ships the SVG marks used by macOS.  The iOS companion hardcodes
   Apple's system icons in `quotaCard` (no equivalent of
   `PlatformLogo`).  Bringing the marks over requires either bundling
   the SVGs in the iOS target or extracting a shared SPM
   `ProviderMarks` package.  This is a downstream-of-F-02 question.
